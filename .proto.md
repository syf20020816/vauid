### 2. SDP 交换时序

```
Publisher 端:                          Server:
  ┌─ SignalRequest.offer ──────────────►  (Publisher's Offer)
  │                                      │
  │                                      ┌─ SignalResponse.offer ──────►  Subscriber 端
  │                                      │  (Server as Offerer to Subscriber)
  │                                      │
  │  ┌─ SignalResponse.answer ◄───────────┘  (Server answers Publisher)
  │  │
  │  │                                    ┌─ SignalRequest.answer ◄─────── Subscriber 端
  │  │                                    │  (Subscriber answers Server)
  │  │                                    │
  │  └─ SignalResponse.answer ◄───────────┘  (Server delivers Subscriber's Answer to Publisher)
  │
  │  ICE Trickle 双向交换:
  ├─ SignalRequest.trickle ─────────────►  (Client → Server, candidateInit 为 JSON)
  │                                         │
  │                                         ┌─ SignalResponse.trickle ──►  (Server → Client)
```

## 总结

LiveKit 的信令协议核心设计思路：

1. **所有消息统一封装在 `SignalRequest` / `SignalResponse` 的 `oneof` 中**，通过 WebSocket 传输
2. **SDP 通过 `SessionDescription` 消息传递**，作为 `offer`/`answer` 字段嵌入 `oneof`
3. **ICE Trickle 通过 `TrickleRequest` 独立传递**，支持分块 Candidate 交换
4. **关键操作通过 `RequestResponse` 机制确认**，使用 `request_id` 做关联
5. **重连场景通过 `SyncState` / `ReconnectResponse` 恢复状态**
6. **节点间信令中继通过 gRPC `Signal` Service 的 `RelaySignal` 实现**
